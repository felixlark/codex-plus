# F6 human windows and native New Window

F6 enters the installed Codex Plus launcher. It reuses the explicitly saved human windows, or a unique existing main window on each intended physical display, and creates only missing windows. Initial screen roles are the observed DELL U3219Q (1) and Mi Monitor (2) (2); their display UUIDs are then saved. Unavailable screens produce a partial failure rather than selecting another display. Repeated requests share the pending creation.

Creation uses the existing host `open-in-new-window` bridge. An accepted native route carries a unique `codexPlusHumanWindow` token. Only the exact token in a native AX WebArea URL establishes the new window's ownership; temporal coincidence, focus and hidden-window geometry do not. The new owned target navigates home while preserving the token. Existing windows are not navigated or reloaded. Native window IDs are saved with host PID and process launch identity. Codex Plus fills the two bound human windows using their exact AX/CG identities; mobile-anchor and utility surfaces are excluded.

Native New Window uses the shared `electron-main-window-bounds` key. Moving a window does not persist that key. The host's already-loaded ESM entry exports its cached module runtime, which supplies `GaA7.appServices.applicationState` and the native remote-call lifetime helper `q77y.P`. Plus verifies the entry SHA before access, reads only this geometry key, saves its original presence/value to an exclusive-create local backup, writes the actual human external-window geometry, then verifies native readback. Existing chats need no reload. Later writes of virtual geometry are corrected on the controller heartbeat while human bindings exist. A damaged backup prevents replacement of the native value; host incompatibility is reported without changing state.

The native launcher publishes the bound human frames to its existing controller pipe. Only a uniquely matching renderer frame receives the preferred target number 1 or 2. Other main targets retain unique numbers from 3 upward. A failed target query preserves the prior mapping. The previous installed app remains available through the existing installer backup. The native geometry backup is `launcher/native-window-bounds-backup.json` under the existing runtime directory and survives Plus/controller restarts.

Acceptance covers allocation with existing hidden targets, ambiguous frames, first-write and restart backup behavior, the installed native New Window menu, both physical frames and visible numbers, and repeated F6 entry without additional windows. Existing hidden frames and the Codex host process must remain unchanged. Software entry verification and a physical F6 press are reported separately.
