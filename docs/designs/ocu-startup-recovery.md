# 登录后自动恢复 OCU 虚拟屏

用户要求：Mac 重启登录后自动恢复 OCU 虚拟屏，Google Chrome 默认进入，不需要手动停车或预先打开 Agent 窗口。

## 当前差异

Plus 已有登录启动、Chrome 默认规则和 OCU 精确窗口托管。AgentDisplay 目前只发现现有屏；OCU 只有在停放窗口时才创建屏。因此重启后没有任何停车请求时，Plus 一直等待不存在的屏。直接用 Chrome 首窗隐式创建会把显示器坐标变化与原位置记录混在一次操作中。

## 实现与边界

1. 在现役 OCU 增加 `ensure_agent_display` 正式工具。它在既有后台状态事务和 AgentDisplay 锁内，读取当前显式 enabled/restoreOnSessionEnd 配置，调用既有 ensureDisplay，登记持屏保留及正常退出钩子。无窗口参数，不定位/移动/关闭任何窗口，不生成占位 UI，不建立第二个 owner；重复调用复用同一个 namespace 屏。关闭 enabled 时不创建。返回当前显示器身份、几何与 persistent 状态；配置为跨回合保留时，空屏也保留到 owner 退出。
2. Plus 在每次启动及恢复总开关时开始调用该正式工具；登录阶段尚未成功时，唤醒和屏幕变化也可推进同一个恢复尝试；只在持久配置开启且总开关开启时恢复。Chrome 开关独立，只决定窗口规则，不阻止恢复其他 Agent 的屏。即使 Chrome 没开窗口也先恢复屏。
3. 恢复分为“等待提供方/恢复中/已连接/具体错误”。同一时刻只有一个恢复请求；主线程继续响应。当前启动的恢复确认完成后停止重试，不把正常 provider 维护/退出自动变成新的重启命令。失败持续重试，默认2秒间隔（UserDefaults `ocuDisplayRecoveryRetryInterval` 可调整，无尝试次数上限）；关闭总开关使后续尝试停止，在途响应先只读对账，不重复动作。正常退出停止恢复，不在收尾重建屏。
4. 先由 OCU 创建/复用屏，再按 namespace vendor/model/serial、非主屏/非镜像/非重叠重新发现；不缓存重启前 ID。恢复 RPC 完成且重新发现通过后，才建立 Chrome watch、读取窗口实际原几何并停放；恢复在途的屏幕通知不提前启动扫描/文件打开。保留已在屏内窗口不重复认领及用户移出窗口不重抢的既有规则。
5. 沿用现有 SMAppService 登录启动入口，交付时核实际 enabled；必要时在现有设置中开启，保留用户以后关闭登录启动的选择，不在每次启动强行重新注册。设置说明登录后自动恢复、等待提供方时的实际状态。维护 OCU 前暂停 Plus 总开关，完成后恢复，避免维护与自动恢复竞争。
