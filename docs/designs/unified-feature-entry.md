## 3. 用户流程

### 3.1 设置

点击页面「Codex Plus」后显示与菜单栏完全相同的原生窗口；重复点击激活已有窗口。关闭设置后继续使用原 Codex 页面，聊天、草稿、当前项目、右侧标签页和任务执行状态保留。设置保存沿用当前 UserDefaults（macOS 应用偏好存储）与既有模型，页面侧不复制一套设置。

设置页保留现有自动展开、屏幕选择、登录启动与状态信息。新增「页面增强」状态，说明是否已接入当前 Codex；显示当前不可用原因和正常恢复方法。页面按钮进入同一设置首页，后续设置按功能分组，当前规模沿用单窗口滚动布局。

### 3.2 贪吃蛇

点击「贪吃蛇」在当前 Codex 页面中央打开 Plus 自有弹层，显示棋盘、当前分数、开始／继续、暂停、重新开始与关闭按钮。游戏使用 HTML Canvas（浏览器内的二维绘图区域），无需聊天、模型调用或网络服务。

- 初次打开处于待开始；方向键和 WASD 控制，空格暂停／继续，Esc 关闭；提供可点击的四个方向按钮。
- 采用固定网格、固定移动节拍；吃食物增长并计分，撞墙／撞自身结束，重新开始清零。食物只生成在空格，填满棋盘显示胜利。
- 游戏键盘事件只在游戏弹层内处理；拦截冒泡，避免方向键、空格、Esc触发宿主聊天操作。其他组合键继续遵循宿主行为，真实验收特别核对 ⌘N。
- 弹层管理焦点并支持 Tab 遍历；关闭后恢复原焦点。开始游戏前保存当前焦点引用，引用失效时聚焦游戏入口。
- 关闭、页面隐藏、窗口失焦时停止游戏推进；隐藏或失焦后回到暂停，用户显式继续。关闭销毁本局，下次打开从待开始进入。
- 切换任务／模式时关闭弹层并销毁本局；页面刷新后从待开始恢复入口。每个窗口有独立局面；同一窗口重复点击聚焦现有弹层。
- 首版只保留内存中的本局分数；无需排行榜、跨窗口同步或新增持久化键。

游戏是完整验证样例：入口挂载 → 点击 → 页面交互 → 关闭 → 释放事件与计时器 → 原聊天继续工作。

## 4. 集成与消息通道

### 4.1 单一运行归属

沿用现有链路：菜单栏 Swift 程序 → 一个 controller.mjs → 官方 Codex 主页面。新增页面入口模块 `feature-entry.mjs` 与独立 `snake.mjs`，由同一控制器装入。用小型静态入口清单定义设置和贪吃蛇的标识、标签、顺序与处理器；避免引入动态插件系统。

页面入口使用 DOM（网页元素树）挂载：Codex Plus 位于左下角原生按钮容器第一项，贪吃蛇插入 `data-sidebar-destination="builtin:projects"` 所在按钮组、紧接 Projects。节点带唯一所有权标识；复制原生按钮的展示类、ButtonInner 包装及六项展示属性，保留自己的标识、名称和动作。使用自有 SVG 图形并继承原生尺寸、颜色与悬停规则，入口不单独覆盖点击区域、内边距或背景。

控制器只向已验签、已校验 PID／监听归属的官方宿主主页面装入模块。目标限制沿用 `mainURL()`，并校验主 frame、默认执行上下文及当前 target；浏览器侧网页、子 frame、Spotlight 等辅助窗口保持原状。宿主匹配与操作区匹配分别返回可诊断原因。

首次装入、真实新窗口与页面重载均执行同一安装方法。页面模块暴露版本、`install`、`dispose` 与只读状态；同版且同一有效连接内重复安装返回已有实例，换版先 dispose。控制器重连属于新连接，即使模块同版也先取消旧请求、销毁旧游戏并重新绑定，恢复到待开始。通过作用于操作区父容器的 MutationObserver（浏览器的元素变化通知）处理宿主重绘，重建缺失的自有入口；完整容器换代时重新定位，无法唯一定位就停止挂载并报告原因。禁止按屏幕坐标或全页文字猜位置。

### 4.2 页面打开原生设置

1. 控制器为主页面默认上下文注册专用 CDP Runtime binding（页面调用后由控制器接收的命名函数）。
2. 页面设置按钮发送版本化的 `open-settings` 消息，带本次 requestId。允许的原生动作只有打开设置。
3. 控制器确认消息来自已登记主 frame 默认上下文，校验固定消息形状，将事件写到子进程标准输出。
4. Swift 把该输出改为 Pipe，按换行解析消息；状态行与 `ui-action` 行明确分类。只接受打开设置，在主线程调用 `showSettings()`。消息不接受路径、命令、任意 URL 或脚本。
5. Swift 经子进程标准输入返回 requestId 和成功／失败；控制器转给同一页面。页面展示明确结果；在等待中重复点击保持单个请求。消息失败清除等待状态，给出从菜单栏打开设置的恢复入口说明。

控制器存活和重连沿用当前 Process 生命周期与轮询；增加父进程退出检测，发现 Plus 已退出就撤销自有页面模块并退出。正常退出时先完成模块卸载、解除 binding 和观察器，再断开 CDP。突发进程终止期间页面请求可能失联，页面等待使用短暂本地反馈超时，超时后恢复可点击并说明连接不可用；只结束本次反馈等待，后端动作以 requestId 确认，恢复后不会重放旧点击。具体反馈时长属于实现时的普通交互参数，在变更记录列明。

既有 `StatusChannel.swift` 的只读 socket 继续只读；不增加本地 HTTP 服务、URL scheme 或网络监听。stdout 的状态行含内部连接信息，Swift 仅解析、保持内存使用，不把完整数据写日志；公开状态与证据只保留必要诊断字段。

## 5. 版本、生命周期、故障与回退

- **当前版本适配**：先审读 26.1106.51428 的资源与真实操作区，重新验证既有排序／重载恢复的结构适配点，审核后更新已支持资源记录。路径和摘要只是候选绑定，结构与行为验证通过后才启用。保持供应商安装包和签名原样。
- **功能状态分开**：设置展示页面入口和项目排序各自的 supported／active／unavailable 状态；原生自动展开保持现有独立状态。页面入口失败后其余已经正常的功能继续运行；共同控制器在某个适配器失败时仍释放暂停的脚本和页面。
- **在用实例**：当前 Codex 使用普通启动；实施设计不强制重载或结束任务。真实接入需要已有自有调试实例，或用户保存工作并正常退出后从 F6 启动。安装与冷启动验收分开记录。
- **重载与多窗口**：每个主页面各自维护入口与游戏；新上下文重新登记 binding，旧上下文销毁时取消待处理请求并释放其映射。重复恢复保持一份入口、一份事件处理器。
- **Plus 退出／重连**：正常退出移除两个入口和游戏、释放全部自有监听及计时器，官方 Codex继续运行。控制器崩溃后沿用 Swift 的恢复机制重新附着，替换旧的模块并取消旧请求；游戏回到待开始。Plus 进程异常退出由父进程检测触发卸载；两者同时强制终止的残留在页面重载时清除，期间不承诺增强可用。
- **宿主更新／结构变化**：未知版本或无法唯一定位时页面增强显示不可用，菜单栏设置仍可打开并显示原因。当前宿主版本已经受支持、仅普通启动未接入时，保存工作并正常退出后经 F6 冷启动即可装入增强。未知版本须先完成 Plus 适配并安装对应候选，再验证正常冷启动；F6 始终启动当前已安装宿主。
- **回退**：保留旧 Plus 安装和候选；退出新 Plus 完成卸载后安装旧版，用户偏好维持。原生聊天／草稿／项目列表由官方 Codex保存，游戏只在内存。旧版 0.3.0 对当前新宿主的页面增强仍按旧兼容范围报告，回退范围需如实记录。

| 控制器恢复与退出 Plus | 控制器异常后可恢复，旧请求不重放；正常退出移除入口与游戏，保留官方任务。重开恢复入口，菜单栏始终可用。 |
| 兼容性与原功能 | 当前宿主真实排序和重载验收通过；未知资源跳过增强、原生页面可用；自动展开、屏幕选择、登录启动与单 runtime 保持。 |

当前交付的安装、真实界面与回归结果见 `docs/acceptance.md` 的 0.4.0 节。本轮沿用当前 chat 实施，未创建或调用新的独立 chat／Goal。用户最终接受继续单独记录。

## 9. 选型取舍与剩余不确定性

- **原生设置窗口复用（采用）／页面重写设置**：复用现有系统设置模型、权限入口和持久化，维护一套真值；网页设置需要新增偏好双向同步，当前需求没有相应收益。
- **沿用控制器与 DOM 挂载（采用）／修改供应商安装包**：内存挂载沿用现有验签与单 owner，更新或退出可清理；安装包修改需要维护供应商资源和签名，增加发布与恢复成本。
- **标准输入输出消息（采用）／新增本地服务或 URL scheme**：现有父子进程已经存在，增加固定消息即可；后两者增加服务或操作系统注册面，当前仅打开设置的需求用不上。
- **Plus 自有页面游戏（采用）／耦合供应商图像等待游戏**：自有模块可直接打开、测试、卸载；供应商游戏带图像消息和上下文依赖，升级接缝更大。

已验证接缝：26.1106.51428 使用 `nav[data-app-navigation-rail="true"]` 的末项容器放置 Plus 第一项；上方 Projects 的稳定目标属性用于定位贪吃蛇及原生展示模板。当前资源的结构适配、页面脚本装入、Runtime binding 与 Swift 消息通道、冷启动和真实多窗口均已执行。路由变化通知使用完整 location 对象，覆盖同页新建聊天；原生 dialog 以显式 margin:auto 居中并使用宿主 `--color-surface` 主题。设置请求反馈超时与提示显示时长均为 5 秒，仅控制界面反馈，不重放原生动作。直接页面重载和后台任务完成的更新版全路径仍分别按验收记录的覆盖边界报告。
