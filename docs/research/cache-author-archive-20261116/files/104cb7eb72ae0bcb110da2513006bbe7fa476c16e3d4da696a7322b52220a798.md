## 阻塞项修复

1. `switch_backup_sqlite_failed` 语义
   - 候选未启动时只读回真实 `previous` release/health/collector。
   - 不调用普通 rollback，不要求或切换到显式 fallback，不要求 fallback plist 已安装。
   - 回执写 `rollback_path=switch_backup_sqlite_failed`、`current_release=previous`。
   - `verify` 按同一 previous 语义校验，拒绝 fallback 冒充。
   - 新增 #188 显式策略用例（`previous=current != fallback`），transaction 与 verify 均覆盖。

2. `rollback-failed-start` 两段补偿
   - 第一段：调用一次 `rollback_failed_start()` 恢复真实 `previous`，独立读回 release/health/collector。
   - 第二段：当 `previous != fallback` 时调用 `rollback_to_fallback(fallback)`，以 fresh 官方 prepare-switch/switch 回指定 fallback，再独立读回。
   - 缺少第二阶段回调、第一阶段读回不符、第二阶段失败均 fail closed，不再出现“只调一次却要求 fallback 成功”。
   - `previous == fallback` 时第一阶段读回即终态。

3. 失败码匹配
   - 支持异常 `failure_code`/`code` 字段、`CalledProcessError.stderr/stdout`、结构化 JSON 的 `failure_code`/`code`/`error`，以及受支持失败码 token。
   - backup 失败码优先于 failed-start 码，避免误路由。
   - 新增真实 `CalledProcessError` 的 backup 与 failed-start 路由测试。

4. PR 正文关联
   - `Closes #188` 已改为 `Delivery-Issue: #188`，不会自动关单。
