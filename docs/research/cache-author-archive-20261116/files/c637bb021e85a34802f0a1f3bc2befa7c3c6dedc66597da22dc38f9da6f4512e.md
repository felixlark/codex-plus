# 私有逐文件链接

iOS 单文件链接使用既有 Smart Shadow HTTPS 服务返回所登记版本的文件内容。目录及 Mac 本地 helper 仍沿原入口；设备路径映射不作为单文件打开的验收证据。

## 接口与认证

GET /api/v2/file-links/:id（及 HEAD）沿既有 Access 本人身份、已授权 grok-bot 委托身份及服务审计，不新增角色、密钥或匿名访问。响应是原始 JSON bytes，Content-Type application/json、inline 文件名、private/no-store、nosniff；没有 Files 根目录跳转。没有 HTTP 登记、上传、删除或任意路径读取接口。

## 显式登记

正式发布者只登记本次获准的具体文件。固定 catalog 路径为 ~/Library/Application Support/SmartShadow/file-links/catalog.json；目录须本人拥有且0700，catalog须本人拥有的0600普通文件且nlink=1，不接受catalog路径别名。程序默认不创建或填充该文件。

格式为 schema=smart-shadow.private-file-links/v1 与 files 数组，每项恰含 id/path/real_path/sha256/size/filename。path 是获准原件的绝对规范路径，real_path 是登记时真实解析路径，filename 必须等于原文件名且为 .json。id = SHA256(UTF8(path + NUL + sha256 + NUL + 十进制size))；它是版本定位符，访问仍须现有认证。禁止把凭据放进URL或catalog。

登记前以真实原件计算完整字节哈希、大小和real_path；不写原件、不伪造Task产物或历史记录。请求只读该精登记列表，拒绝源文件symlink/hardlink、所有权/写权限异常、路径漂移及内容/大小变化。读取同一fd，前后stat与当前路径稳定后才发送；版本变化返回409，由原发布者核原件后重新登记，不自动扩大列表或读取新版本。

## 验证与发布

测试覆盖真实临时文件、别名/权限/版本漂移、现有认证与审计、无写入路由，以及原目录helper兼容。发布时由原结果owner将精审代码与私catalog串行安装，并经正式HTTPS分别回读获准原件的status/bytes/SHA及未认证拒绝。隔离HTTP或Mac测试不等于iOS验收；本事项由用户自行验收手机上的五个文件。

## 新增限制

新增端点仅读取显式登记的JSON版本，要求上述私catalog、普通文件身份及完整性；依据是本需求只授权命名的五份原件，不授权公共分享或任意文件读取。现有身份及grok-bot委托权限不变，没有新增资源上限、并发槽、退避或超时；此范围须由原仓库负责人定稿后合并。
